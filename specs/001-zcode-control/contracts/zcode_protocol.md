# Contract: `zcode_protocol`

**Purpose**: the escape hatch. Raw access to any ZCode Protocol method.
Implements Constitution Article I's substitution principle: a bounded typed surface for normal use, and
one auditable, gated, kill-switchable door for everything else.

**Mutating when the method is.** Rating **C** — always reported `unreliable` in warnings.

## Actions

| Action | Arguments | Notes |
|---|---|---|
| `methods` | `filter?` | baked-in catalog: 66 methods, annotated `read_only` / `mutating`, with `source` |
| `call` | `method`, `params?`, `workspace?`, `session_id?`, `timeout_ms?` | raw invocation |

```ts
zcode_protocol({ action: 'methods', filter: 'workspace/' })
zcode_protocol({ action: 'call', method: 'workspace/readState',
                 params: { workspace: { workspacePath: '…', workspaceKey: '…' } } })
```

## Gating (three independent controls)

1. **Kill switch** — `ZCODE_MCP_DISABLE_PROTOCOL=1` disables the tool entirely (mirrors the sibling
   server's `UE_MCP_DISABLE_SCRIPT` convention).
2. **Allowlist** — `ZCODE_MCP_PROTOCOL_ALLOW` (comma-separated globs) restricts which methods may be
   called. **Default allowlist is read-only paths only:**
   `session/*`, `workspace/readState`, `v4/commands/query`, `mcp/list`, `usage/stats`, `plugins/list`,
   `automation/list`, `skills/referenceCatalog`, `process/*`, `interaction/browserList`.
3. **Mutation gate** — any method the catalog classifies `mutating` additionally requires
   `ZCODE_MCP_PROTOCOL_ALLOW_MUTATIONS=1`.

A refused call returns `ok:false`, `reasonCode:'mcp.protocol.disabled'` /
`'mcp.protocol.method_not_allowed'` / `'mcp.protocol.mutations_disabled'`, and **touches no process**.

## Always-degraded warning

Every successful `call` carries:

```json
{"code":"raw_protocol","impact":"unreliable",
 "detail":"raw protocol call — no semantic validation, no read-back, and no schema guarantee were applied"}
```

This is the point: a caller reaching for the escape hatch is told, in the result itself, that the
guarantees the typed tools provide do not apply here.

## Method catalog

`data/zcode_protocol_methods.json`, regenerated by `tools/zcode_methods.py` from the installed bundle,
containing per method: `{name, namespace, read_only, mutating, source, since?}`.

At first contact the server compares the **live** protocol identity and method availability against the
catalog. On mismatch:

- unknown method → `-32601` passed through, `impact:'degraded'`
- catalogued method missing from the live runtime → `warnings:[{code:'catalog_drift', impact:'degraded'}]`
- protocol name/version different → `warnings:[{code:'protocol_version_mismatch', impact:'unreliable'}]`

Never silent. Article III.

## Failure modes

| Condition | Result |
|---|---|
| Tool disabled | `ok:false`, `mcp.protocol.disabled` |
| Method not in allowlist | `ok:false`, `mcp.protocol.method_not_allowed`, message names the effective allowlist |
| Mutating method without gate | `ok:false`, `mcp.protocol.mutations_disabled` |
| `-32602` invalid params | `ok:false`, path-qualified zod message, `impact:'unreliable'` (schema drift) |
| Payload over 1 MiB | `ok:false` before send |
| Unknown method | `ok:false`, `-32601` verbatim |

## Permissions

This tool can reach methods no typed tool exposes. Three consequences, all deliberate:

1. It is **off by default** for mutations, so the typed surface remains the contract that tests cover.
2. It cannot be used to reach UI automation, direct database writes, or the credential store — those are
   not protocol methods, so the allowlist cannot express them.
3. Its results are always marked `unreliable`, so an automated caller that routes on
   `warnings[].impact` will treat them with appropriate suspicion.

## Notes

- `methods` is also the discovery mechanism for planning new typed tools: any method that proves
  valuable through the escape hatch should graduate into a typed action with a read-back.
- This tool is the reason the typed surface does not need to cover all 66 methods to be complete.
